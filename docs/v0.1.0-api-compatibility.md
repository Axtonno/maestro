# Maestro v0.1.0 Public API Compatibility

Data: 2026-08-15

## Verdetto

La v0.1.0 pubblica contratti utilizzabili ma **sperimentali**. Non dichiara uno
SDK stabile. La versione `0.x` può introdurre breaking change, che devono essere
esplicitati nel changelog; lo schema di configurazione deve cambiare versione
quando il significato o la struttura diventano incompatibili.

## Superficie di prodotto

| Contratto | Stato | Regola v0.1.0 |
|---|---|---|
| Comandi CLI | Sperimentale | nomi e exit code documentati per l'artifact v0.1.0 |
| Output line-oriented | Sperimentale | stdout risultato, stderr operativo; non è ancora uno schema machine API stabile |
| YAML `version: 1` | Sperimentale e strict | unknown/duplicate field e versioni diverse sono rifiutati |
| Artifact/manifest | Pubblicato | nome, versione, commit, piattaforma, licenza e stato esatti |
| Configurazione inclusa | Supportata | solo profilo read-only della compatibility matrix |

## Package Go importabili

Il modulo espone il package root `github.com/antonio-cafeo/maestro` e:

```text
pkg/agent
pkg/benchmark
pkg/contextengine
pkg/gestor
pkg/plugin
pkg/plugin/laravel
pkg/provider
pkg/provider/llamacpp
pkg/provider/ollama
pkg/runtime
pkg/tool
```

Questi package hanno constructor, interfacce, value object, sentinel ed eventi
tipizzati verificati dai rispettivi audit, ma restano API sperimentali. Non è
promessa compatibilità source o binary fra versioni minori `0.x`.

`internal/` è escluso per definizione dall'API pubblica. File sotto `cmd/`,
script, fixture e report non sono librerie importabili.

## Invarianti mantenuti nella v0.1.0

- target espliciti e assenza di selezione automatica;
- snapshot/value object difensivi e validazione al boundary;
- errori ispezionabili tramite `errors.Is`/`errors.As` dove documentato;
- eventi con payload allowlist e senza dettagli esterni arbitrari;
- `Decision` non è un permit e l'authorization resta exact-action;
- chiamate provider/tool cancellabili e bounded;
- nessun accesso consumer ai tipi `internal`.

## Audit di riferimento

Gli inventari dettagliati sono mantenuti nel repository sorgente:

- `provider-api-compatibility-audit.md`;
- `plugin-api-compatibility-audit.md`;
- `context-engine-api-compatibility-audit.md`;
- `agent-system-api-compatibility-audit.md`.

La release non stabilizza automaticamente tutte le capability implementate:
la matrice di prodotto in `compatibility.md` resta più stretta della superficie
Go e prevale sulle inferenze tratte dal codice.

## Evoluzione

Prima di dichiarare un SDK stabile serviranno almeno una policy di
deprecazione, compatibility test fra release, versionamento delle estensioni e
documentazione separata per consumer Go. Questi obiettivi sono successivi alla
v0.1.0.
