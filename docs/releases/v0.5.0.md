# Maestro v0.5.0

Stato: **rilasciata e verificata**.

Maestro v0.5.0 è una workstation AI locale delimitata: Direct Chat legge zero
o un file esplicito; Controlled Mutation propone e applica una sostituzione
host-bound soltanto dopo preview e allow-once. Il runtime modulare resta la
fondazione del prodotto, non un sinonimo di autonomia già disponibile.

Report finale M36: `docs/reports/milestone-36-final.md`.

Report M37: `docs/reports/milestone-37-final.md`. Ambiente:
`docs/reports/milestone-37-environment.yaml`.

Report M38: `docs/reports/milestone-38-final.md`. Ambiente nativo:
`docs/reports/milestone-38-environment.yaml`.

Decisione release: `docs/milestone-37-release-decision.yaml`.

Percorso operativo: [Installa e prova](../install-and-try.md). Perimetro del
write-mode:
[Controlled Mutation: perimetro supportato](../controlled-mutation-support.md).

La linea v0.5.0 productizza Controlled Mutation host-bound con due profili
locali separati: `qwen3.5:9b` per Direct Chat e `qwen2.5-coder:14b` per la
mutazione controllata. La capability resta opt-in tramite
`maestro workspace replace` e richiede profilo v4, TTY reale, preview completa
e approvazione allow-once esplicita.

## Support claim

Su Linux amd64 in WSL2, sul reference hardware qualificato con RTX 5070 da
12 GB, Ollama locale e i modelli/digest distribuiti, Maestro può modificare un
intervallo esplicitamente selezionato in un singolo file PHP sotto `app/`, dopo
preview e approvazione esplicita, utilizzando `qwen2.5-coder:14b`.

Target artifact: `linux_amd64`. Piattaforme osservate: `Windows → WSL2 →
filesystem Linux` con RTX 5070 e Linux amd64 nativo CPU-only su ThinkPad T490s
con Intel Core i5-8365U. La prova nativa M38 usa lo stesso asset pubblico e gli
stessi digest; qualifica i gate aggregati di adozione sul campo, senza
estendere il claim a ogni hardware Linux amd64.

Non sono inclusi individuazione autonoma del target, multi-file, inserimenti
arbitrari, agent, mutazioni senza TTY, altri linguaggi o directory e modelli o
hardware non qualificati.
