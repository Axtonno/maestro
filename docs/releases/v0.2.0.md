# Maestro v0.2.0

Data: 2026-08-21

Stato: release.

## Sintesi

v0.2.0 mantiene il percorso di prodotto Linux `amd64`, Ollama e Laravel
read-only della v0.1.1. La configurazione inclusa espone soltanto
`workspace.list`, `workspace.read` e `workspace.search` e imposta
`workspace_mutate: deny`.

La release contiene contratti e benchmark sperimentali sviluppati per
Controlled Mutation, ma non li promuove al supporto. Il candidato live della
Milestone 11 ha fallito Gate A; ADR-0032 registra `mutation_deferred`.

## Novità tecniche

- preview bounded e content-bound per invocation preparate;
- risultati ed eventi redatti per distinguere apply, durability e reindex;
- `workspace.patch` atomica su Linux nel profilo sperimentale;
- benchmark Controlled Mutation versionato con matrice deterministica e gate
  live fail-fast;
- lettura deterministica tramite Tool Runtime per le istruzioni esplicite
  `Read <logical-path> ...`, con policy, containment e hard limit invariati;
- recovery redatta degli arguments invalidi per i soli tool read-only;
- contratto API v0.2.0 aggiornato con le aggiunte Go additive.

## Qualificazione

Il percorso supportato ha superato packaging riproducibile, installazione
esterna al checkout, doctor 9/9, due quick start consecutivi sul release
candidate, SIGINT, deadline, hard limit e scansione anti-leak. Ogni quick start
ha osservato una read reale e ha lasciato la fixture byte-identica.

Il release candidate non viene rinominato come release: l'artifact finale
`maestro-v0.2.0-linux-amd64.tar.gz` è costruito separatamente da un commit
successivo al congelamento di queste note.

## Supporto ufficiale

- Linux `amd64`;
- Ollama locale su endpoint esplicito;
- `llama3.1:8b` per il reference agent Laravel read-only;
- `embeddinggemma:latest` come fixture embedding;
- tool `workspace.list`, `workspace.read` e `workspace.search`;
- configurazione YAML strict `version: 1`.

## Non supportato

- `workspace.write`, `workspace.patch` e approval mutativa;
- `ibm/granite4.1:8b` come fixture di prodotto;
- llama.cpp;
- sandbox, recovery, shell, Git, multi-agent e tool di terze parti.

## Upgrade dalla v0.1.1

CLI, exit code e schema YAML read-only non cambiano. Estrarre l'archive in una
directory nuova, verificare checksum, manifest e `maestro version`, quindi
riutilizzare la configurazione soltanto dopo `maestro doctor`.

Non copiare o abilitare `configs/maestro.mutating.example.yaml`: il file non è
incluso nell'archive e resta materiale sperimentale del repository sorgente.

## Sicurezza

Maestro resta trusted in-process e usa i privilegi dell'utente locale. Il
profilo read-only riduce l'autorità esposta al modello ma non costituisce una
sandbox. Consultare `security-model.md`, `compatibility.md` e
`known-issues.md` prima di usare workspace sensibili.
