# Maestro v0.2.0 Public API Compatibility

Data: 2026-08-21

## Verdetto

La v0.2.0 pubblica contratti utilizzabili ma **sperimentali**. Non dichiara uno
SDK stabile. La serie `0.x` può introdurre breaking change, che devono essere
esplicitati nel changelog; lo schema di configurazione deve cambiare versione
quando significato o struttura diventano incompatibili.

Rispetto alla v0.1.1, CLI e schema YAML `version: 1` del percorso supportato non
cambiano. Le aggiunte ai package Go per preview e lifecycle mutativo sono
additive e sperimentali; non ampliano la compatibility promise di prodotto.

## Superficie di prodotto

| Contratto | Stato | Regola v0.2.0 |
|---|---|---|
| Comandi CLI | Sperimentale | nomi ed exit code documentati per l'artifact v0.2.0 |
| Output line-oriented | Sperimentale | stdout risultato, stderr operativo; non è uno schema machine API stabile |
| YAML `version: 1` | Sperimentale e strict | unknown/duplicate field e versioni diverse sono rifiutati |
| Artifact/manifest | Pubblicato | nome, versione, commit, piattaforma, licenza e stato esatti |
| Configurazione inclusa | Supportata | solo profilo read-only della compatibility matrix |

## Package Go importabili

Il modulo espone il package root `github.com/antonio-cafeo/maestro` e:

```text
pkg/agent
pkg/benchmark
pkg/contextengine
pkg/gestor
pkg/plugin
pkg/plugin/laravel
pkg/provider
pkg/provider/llamacpp
pkg/provider/ollama
pkg/runtime
pkg/tool
```

Questi package restano API sperimentali. Non è promessa compatibilità source o
binary fra versioni minori `0.x`. `internal/` è escluso per definizione; file
sotto `cmd/`, script, fixture e report non sono librerie importabili.

## Delta pubblico dalla v0.1.1

Le aggiunte esportate principali sono:

- sentinel `agent.ErrMutationFailed` e `agent.ErrContextRefreshFailed`;
- evento redatto `agent.EventMutationTransitioned` e tipi
  `MutationStage`, `MutationStatus`, `MutationEffect` e
  `MutationEventPayload`;
- `tool.Preview`, `tool.PreviewField` e relativi constructor/accessor bounded;
- `tool.NewPreparedInvocationWithPreview` e accessor `Preview`, mantenendo
  invariato `NewPreparedInvocation`;
- `tool.EffectState` e metadata di effetto/durability sui risultati.

Non sono stati rimossi o rinominati comandi, campi YAML o constructor pubblici
del percorso read-only. Queste aggiunte supportano codice sperimentale presente
nel repository, ma `workspace.patch`, approval mutativa e relativo agent non
sono supportati dall'artifact v0.2.0.

## Invarianti mantenuti

- target espliciti e assenza di selezione automatica;
- snapshot/value object difensivi e validazione al boundary;
- errori ispezionabili tramite `errors.Is`/`errors.As` dove documentato;
- eventi con payload allowlist e senza dettagli esterni arbitrari;
- `Decision` non è un permit e l'authorization resta exact-action;
- chiamate provider/tool cancellabili e bounded;
- nessun accesso consumer ai tipi `internal`;
- configurazione inclusa limitata a list/read/search con deny mutativo.

## Audit di riferimento

Gli inventari dettagliati sono mantenuti nel repository sorgente:

- `provider-api-compatibility-audit.md`;
- `plugin-api-compatibility-audit.md`;
- `context-engine-api-compatibility-audit.md`;
- `agent-system-api-compatibility-audit.md`.

La matrice di prodotto in `compatibility.md` resta più stretta della superficie
Go e prevale sulle inferenze tratte dal codice.

## Evoluzione

Prima di dichiarare un SDK stabile serviranno almeno una policy di
deprecazione, compatibility test fra release, versionamento delle estensioni e
documentazione separata per consumer Go. Questi obiettivi restano successivi
alla v0.2.0.
