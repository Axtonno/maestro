ADR-0020 – Embedded Developer Dataset and Non-LLM Transparent Rubrics

- **Contesto**: il Developer Benchmark deve misurare task PHP/Laravel reali senza dipendere da repository utente, rete, evaluator LLM o output sensibili nei report. La baseline del plugin Laravel deve essere esercitata realmente. Stato tecnico e qualità non sono equivalenti: una risposta può essere valida a livello di protocollo ma poco utile. Un evaluator testuale libero potrebbe inoltre copiare prompt, sorgenti o risposta nel report.
- **Decisione**: Maestro incorpora `maestro-laravel-mini@1.0.0`, un progetto fixture privo di dati sensibili con cinque task generativi e un task di retrieval embedding. La fixture viene materializzata in una directory temporanea privata soltanto per il lifecycle del plugin Laravel e rimossa allo shutdown. Le completion sono valutate con tre criteri lessicali pubblici; il retrieval usa ranking cosine e assegna 3/2/1/0 in base al primo risultato rilevante. `Sample.State` conserva il risultato tecnico, mentre `Sample.Evaluation` registra separatamente evaluator, metodo, score 0–3 e un `rationale_code` validato. Prompt, risposte e embedding non vengono serializzati. Un gate qualitativo è soltanto opt-in tramite `--minimum-score`.
- **Conseguenze positive**: ogni run usa gli stessi file e la stessa versione; il plugin Laravel è parte effettiva della configurazione; il benchmark resta offline-testable; score e motivazione sono riproducibili e auditabili; uno score basso non viene confuso con un errore provider; nessun modello evaluator aggiunge costo, variabilità o dipendenze; i campi qualitativi non possono contenere testo libero sensibile.
- **Conseguenze negative e trade-off**: la checklist lessicale misura evidenze, non correttezza completa; risposte semanticamente valide possono perdere punti e risposte opportunistiche possono guadagnarli; il codice generato non viene eseguito; il dataset iniziale è piccolo e inglese; la materializzazione richiede filesystem temporaneo; la risposta non è disponibile nel report per una revisione retrospettiva.
- **Alternative considerate**: repository Laravel esterno clonato durante la run, workspace dell'utente come dataset, fixture non versionate, evaluator LLM obbligatorio, un singolo score globale, qualità trasformata in stato `failed`, risposte complete nel report, rationale testuale libero, plugin Laravel soltanto dichiarato nel profilo senza lifecycle reale e retrieval rinviato al Context Engine.
