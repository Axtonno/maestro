ADR-0021 – Canonical JSON, Deterministic Markdown and Declarative Hardware Metadata

- **Contesto**: automazione e confronto richiedono un formato raw stabile, mentre lettura e condivisione richiedono una vista umana. Generare i due formati da percorsi diversi rischierebbe divergenze e redazione incoerente. Il profilo deve descrivere l'hardware senza introdurre dipendenze da tool GPU, agent di telemetria o comandi non portabili. Input e output di un renderer possono inoltre causare perdita del JSON se coincidono.
- **Decisione**: JSON `1.2.0` resta la fonte canonica. `EncodeReportMarkdown` consuma esclusivamente un `benchmark.Report` validato e la stessa copia redatta del serializer JSON. `maestro bench render` usa un decoder strict con limite 64 MiB e rifiuta input/output coincidenti. I quattro comandi live espongono `--markdown` opzionale e mantengono stdout riservato al JSON. Entrambi i file sono atomici e `0600`. Il profilo comune usa Go runtime, procfs Linux e build info; GPU, backend e VRAM sono metadata dichiarativi opt-in, validati e normalizzati. Nessun probe esterno viene eseguito e i valori assenti restano omessi.
- **Conseguenze positive**: Markdown e JSON non divergono; la redazione ha un solo confine; un report può essere renderizzato nuovamente senza provider; output parziali non vengono pubblicati; l'hardware profile è uniforme tra Smoke, Runtime e Developer Benchmark; nessuna dipendenza esterna o rete è necessaria; l'assenza non viene confusa con zero; non viene creato uno score globale.
- **Conseguenze negative e trade-off**: il renderer accetta soltanto lo schema corrente; report storici richiederanno in futuro una migrazione esplicita; procfs limita CPU e RAM dettagliate a Linux; i metadata GPU dipendono dall'accuratezza dell'utente; JSON e Markdown sono atomici singolarmente ma non costituiscono una transazione a due file; il Markdown include tutti i campioni e può diventare lungo.
- **Alternative considerate**: Markdown come fonte primaria, template che legge direttamente output provider, renderer permissivo con campi sconosciuti, output Markdown su stdout insieme al JSON, sovrascrittura in-place del report, probing automatico tramite comandi GPU, dipendenza obbligatoria da OpenTelemetry/Prometheus, zero per dati assenti e score qualitativo globale.
