ADR-0005 – Synchronous In-Process Event Bus

- **Contesto**: i componenti del Runtime devono comunicare senza riferimenti diretti e senza introdurre dipendenze esterne o un'infrastruttura distribuita prima che esista una reale esigenza.
- **Decisione**: adozione di un Event Bus in-process con dispatch sincrono, corrispondenza esatta dei topic, più handler ordinati per topic, snapshot dei subscriber per ogni pubblicazione e accesso thread-safe.
- **Conseguenze positive**: comportamento deterministico, backpressure esplicita, API minimale, callback reentranti e assenza di goroutine o code nascoste.
- **Conseguenze negative e trade-off**: un handler lento ritarda il publisher, gli errori asincroni non sono modellati e `Unsubscribe(topic)` rimuove tutti gli handler del topic secondo il contratto pubblico corrente.
- **Alternative considerate**: dispatch asincrono implicito, un worker pool interno, un handler unico per topic e un broker esterno.
