ADR-0026 – Release-Oriented v0.1.0 Product Boundary

- **Stato**: Accepted.
- **Contesto**: la Milestone 7 dimostra con gate deterministici che Tool System e Agent System sono composti, bounded, permission-gated e workspace-aware. Il risultato è consumabile da codice Go, ma non costituisce ancora un prodotto installabile e configurabile da un utilizzatore esterno. Mancano configuration contract, CLI di prodotto, approval terminale, artifact, installazione pulita e scenario agentico live completo.
- **Decisione**: il gate post-Milestone 7 dà GO alla Milestone 8, ridefinita come productization della v0.1.0. La milestone non introduce un ecosistema generalizzato: consegna il percorso minimo `install -> configure -> doctor -> inspect -> run -> approve -> verify` per il reference agent su un workspace locale reale.
- **Decisione**: la piattaforma ufficiale iniziale è Linux `amd64`, unica combinazione oggi coperta dalle evidenze repository-wide e destinata alla prova d'installazione pulita. Altri artifact possono essere prodotti soltanto come sperimentali finché non superano build, avvio, help, version e doctor sulla piattaforma dichiarata; diventano supportati solo dopo una prova documentata.
- **Decisione**: il percorso provider ufficialmente validato usa Ollama con `llama3.1:8b` per chat/tool calling e `embeddinggemma:latest` per embedding. `qwen2.5-coder:7b` resta il caso negativo canonico per tool calling nella combinazione Ollama verificata e non è una fixture supportata per il reference agent mutante.
- **Decisione**: llama.cpp è candidato al supporto ufficiale, ma rimane condizionato alla presenza di una matrice live documentata che copra le capability necessarie. Nel repository e nella cronologia Git disponibili al 2026-08-13 non è presente `reports/milestone-3-live-llamacpp-validation.md`; non è quindi possibile certificare localmente il completamento indicato da fonti successive. Prima della release il report deve essere aggiunto e verificato oppure llama.cpp deve essere dichiarato sperimentale tramite una decisione esplicita.
- **Decisione**: la configurazione pubblica iniziale è un singolo documento YAML strict con `version: 1`. Provider, modello, workspace, agente, policy, tool set e limiti sono espliciti; campi sconosciuti o duplicati falliscono. I secret vengono referenziati tramite ambiente e non memorizzati nel documento.
- **Decisione**: la CLI minima della v0.1.0 è `maestro doctor`, `maestro models`, `maestro agents`, `maestro run` e `maestro version`. Help, stdout/stderr e codici di uscita fanno parte del contratto sperimentale. I comandi benchmark restano disponibili ma non definiscono il quick start.
- **Decisione**: CLI, schema config, composition root e package Go pubblici sono contratti sperimentali intenzionali della serie 0.x. I formati serializzati cambiano soltanto tramite versione schema; cambi breaking richiedono note di release e migrazione. `internal/` non è API e non viene introdotta una promessa SDK 1.x.
- **Decisione**: il security model resta trusted in-process. Permission e approval governano il percorso orchestrato ma non costituiscono sandbox, isolamento OS o difesa da codice Go ostile nello stesso processo. Tool, agenti e plugin di terze parti non sono parte del percorso supportato.
- **Decisione**: sono esclusi da v0.1.0 sandbox, isolamento di processo, memoria persistente, recovery, multi-agent, remote execution, shell/Git/Docker completi, secret manager, packaging generalizzato di estensioni, SDK stabile e selezione automatica di provider o modello.
- **Decisione**: la release è accettata soltanto dopo artifact versionato e checksum, installazione pulita fuori dal checkout, quick start Laravel, approval allow/deny, cancellazione e limiti verificati, scenario live Ollama completo, risoluzione della matrice llama.cpp, documentazione pubblica, licenza, compatibility matrix e gate repository-wide verdi.
- **Conseguenze positive**: la Milestone 8 ha un termine verificabile; supporto e fixture non vengono dedotti dalla sola presenza di adapter; il primo utilizzatore dispone di un percorso piccolo, esplicito e riproducibile; limiti di sicurezza e stabilità sono dichiarati prima della pubblicazione.
- **Conseguenze negative e trade-off**: il supporto iniziale è ristretto; llama.cpp può rimanere sperimentale nonostante l'adapter implementato; la configurazione strict richiede più dichiarazioni; la serie 0.x non promette stabilità SDK; packaging e documentazione diventano gate bloccanti quanto i test del runtime.
- **Alternative considerate**: mantenere Milestone 8 come “Ecosistema”, pubblicare direttamente le API Go senza CLI, supportare ogni piattaforma compilabile, inferire provider/modello dal primo elemento disponibile, considerare llama.cpp validato senza report locale, presentare permission come sandbox, includere plugin terzi o rinviare installazione e security model a dopo il tag.
